이번 빌드 목적: SKT / SKB 「측량공정진행현황」 원본 양식을 그대로 업로드
────────────────────────────────────────────────────────────────

■ 0. 왜 기존 버전으로는 안 올라갔나
   BUILD 01까지는 머리글에 "순번"과 "공구"가 있는 줄을 찾아 표를 인식했습니다.
   두 원본 파일에는 순번도 공구명도 없어서 업로드 자체가 실패했습니다.
   그 밖에도 시트가 여러 개이고, 시트마다 칸 수가 다르고, 안내용 예시 줄이
   섞여 있고, 발주처 칸이 없는 등 구조가 전부 달랐습니다.

────────────────────────────────────────
■ 1. 머리글 자동 탐색 (고정 규칙 → 점수 방식)
────────────────────────────────────────
상위 20줄을 훑어 인식 가능한 항목이 가장 많은 줄을 머리글로 잡습니다.
  · SKT 파일 : 1행이 머리글
  · SKB 파일 : 1행은 안내줄, 2행이 머리글 → 2행을 정확히 집어냄
머리글 위아래에 있는 안내용 예시 줄("공사명 / 측량거리(km) / 년도 …")은
자동으로 걸러냅니다. (SKT 타지사 시트 2행)

────────────────────────────────────────
■ 2. 원본 양식 머리글 인식 추가
────────────────────────────────────────
  정산거리(km)      ← 실측거리(정산거리)      ※ 금액 계산 기준
  측량거리(km)      ← 측량 심사내역
  발주처            ← 사업자
  공구명/공사명      ← 공사명
  측량구분          ← 측량방법
  지사              ← 지역본부
  진행상황          ← 측량예정일
  정산상황          ← 측량 정산완료
  정산금액          ← 측량비 정산예정금액(원)
  사업구분(Tango)   ← 사업유형
  시행시기          ← 시행시기 / 년도
  Eng 번호          ← Eng 번호
  순번              ← 대원 관리번호

머리글 안의 줄바꿈·공백은 무시하고 비교합니다
("실측거리\n(정산거리)" 같은 칸도 정상 인식).

중요: "실측거리(정산거리)"를 정산 기준 거리로, "측량 심사내역"을
측량거리로 나눠 인식합니다. 두 칸 모두 거리라서 순서를 잘못 잡으면
금액이 틀어지는 지점이라 우선순위를 명시했습니다.

────────────────────────────────────────
■ 3. 여러 시트 지원 + 시트 선택 화면 (신규)
────────────────────────────────────────
파일을 올리면 시트 목록이 먼저 뜹니다.
  · 시트별 건수 / 머리글 행 / 칸 수 표시
  · 데이터가 없는 시트(요약표 등)는 사유와 함께 자동 제외
    예) SKB "정산확인" 시트 → "표 머리글을 찾지 못함"
  · 체크로 원하는 시트만 선택

여러 시트를 함께 불러와도:
  · 공사코드 + 공사명이 같은 건은 한 번만 들어갑니다
    예) SKB 5개 시트 합계 516건 → 중복 제거 후 273건
  · 시트마다 칸 구성이 달라도 머리글 이름 기준으로 하나로 합칩니다
    예) SK TNS 시트에만 있는 "성과심사비 / TNS 정산일정 / sap 입력명칭"도
        칸으로 살아남음 (통합 27칸)

────────────────────────────────────────
■ 4. 발주처 자동 판정 (신규)
────────────────────────────────────────
원본의 "사업자" 칸에는 SK TNS·(주)팬텍씨앤아이엔지니어링·유엔에이엔지니어링
같은 도급사명이 들어 있어 발주처로 쓸 수 없습니다.

  1) 사업자 칸 값이 SKT / SKB / 원인자면 그대로 사용
     → SKT 파일에서 원인자 8건이 정상 분리됨
  2) 아니면 시트 선택 화면에서 고른 "이 파일의 발주처"로 채움
  3) 파일명에 SKT / SKB가 있으면 미리 선택해 둠 (두 파일 모두 자동 적중)
  4) 결과를 "발주처(자동)" 칸으로 따로 만들어 화면에서 보고 고칠 수 있음
     원본 "사업자" 칸은 도급사 정보로 그대로 남습니다

누적 업로드 시 먼저 넣은 파일의 발주처는 유지되고, 새로 들어온 줄만
새 파일의 발주처로 채웁니다.
  검증: SKB 273건 위에 SKT 549건 누적 → 822건, 발주처 SKB·SKT·원인자 공존

────────────────────────────────────────
■ 5. 정산상황 정규화 (신규)
────────────────────────────────────────
원본 값이 제각각이라 그대로는 필터가 불가능했습니다.
  "정산완료" "미지급" "정산제외" "24년 8월" "9월 지급 확정"
  "9월 50% 기성예정" "예원 지급예정" "26년 7월 누락" "측량불가" …

4가지로 정리해 필터·집계에 쓰고, 원본 문구는 칸에 그대로 보여줍니다.
  정산완료  ← 정산완료 / 지급 / 입금 / "24년 8월" 같은 월 표기
  정산예정  ← 예정 / 확정 / 진행중 / 대기
  미정산    ← 미지급 / 미정산 / 미결제 / 누락
  정산제외  ← 제외 / 불가 / 취소

  SKT 549건 → 완료 476 / 예정 15 / 미정산 14 / 제외 5 / 빈칸 39
  SKB 273건 → 완료 171 / 예정 34 / 미정산 21 / 제외 7 / 빈칸 40

────────────────────────────────────────
■ 6. 구분 칸 자동 생성 + 선택 일괄입력 (신규)
────────────────────────────────────────
정산내역서 양식에는 "구분"이 필요한데 두 원본 양식에는 없습니다.
  · 업로드 시 빈 "구분" 칸을 자동으로 만들고 안내 문구를 띄웁니다
  · 리스트관리에 "선택 일괄입력" 버튼 추가
    줄을 체크 → 칸 선택 → 값 입력 → 한 번에 채우기
    검증: SKB 273건 "지자체" 일괄 입력 확인

────────────────────────────────────────
■ 7. 그 밖의 조정
────────────────────────────────────────
7-1. 누적 업로드가 새 칸을 버리지 않고 뒤에 추가하도록 변경
     (BUILD 01은 기존 목록에 없는 칸을 버렸음)
7-2. 합계행·빈 줄 방어를 "실제로 존재하는 칸"만 근거로 판단하도록 수정
     (칸이 없는 간단한 표에서 전 줄이 사라지던 문제)
7-3. 발주처가 SKT·SKB·원인자가 아니라는 이유로 줄을 버리지 않음
     → 발주처 미정 건은 버리는 대신 경고로 표시
7-4. 업로드 미리보기는 앞 300건만 그려 대용량에서 느려지지 않게 함
7-5. 같은 머리글이 두 번 나오면 뒤엣것에 번호를 붙여 구분
     (SKT·SKB 양식 모두 "비고"가 두 번 나옴)

■ 9. 사용 순서
────────────────────────────────────────
 1) 사업추가 → 엑셀 업로드 → 파일 올리기
 2) 시트 선택 화면에서 가져올 시트 체크 + 발주처 확인
    → "선택한 시트 불러오기"
 3) 컬럼 인식 결과 / 데이터 점검 확인
 4) "선택한 사업 → 리스트관리로"
 5) 리스트관리에서 구분 등 빈 칸 채우기 (선택 일괄입력)
 6) 정산리스트 → 대상 선택 → 내보내기

두 파일을 함께 관리하려면 첫 파일은 "기존 목록 교체",
두 번째 파일은 "기존 목록에 추가"로 올리면 됩니다.

■ 10. 확인 부탁드릴 것
────────────────────────────────────────
· 정산 기준 거리를 "실측거리(정산거리)" 칸으로 잡았습니다. 맞는지 확인 필요.
· 정산내역서의 "구분"에 어떤 값이 들어가야 하는지 알려주시면
  발주처·사업유형에서 자동으로 채우도록 규칙을 넣겠습니다.
· 공사코드 중복 (SKT 4건 / SKB 17건)은 원본 데이터 자체의 중복입니다.
  리스트관리에서 "공사코드 중복" 칩을 눌러 확인해 보세요.
· 안전관리비율을 정산시스템 본체와 대조하려면 generate.py가 필요합니다.
